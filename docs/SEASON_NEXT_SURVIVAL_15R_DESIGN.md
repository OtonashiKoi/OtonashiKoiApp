## 二、現況量測（問題有多大）

> 現況請看下面的「改版後實測」與 `docs/balance-reports/` 最新報告。

| 量測項 | 數值 | 對 15 回合的距離 |
|---|---|---|
| 基準玩家 maxHp（VIT24＋真實防具） | **575** | — |
| 每回合期望承傷（巨血探針實測） | **546** | 需 ≤ 38 → **差 14.4 倍** |
| 最大單發（大成功/爆擊） | ~650 | 需 ≤ 230 → **單發即超過 113% 血量＝字面秒殺** |
| 極限閃避（AGI54→dodge 47.5）承傷 | 532/回合 | **幾乎無效**（僅 −3%），因 boss hit 100 ＋ 31% 攻擊必中（大成功26%+完美5%無視迴避） |
| 極限減傷（pctDef 85 cap）承傷 | ~82/回合 | 有效，但現實裝備給不到（見下） |
| 全遊戲防具 VIT 理論極限（每槽最高加總） | **111**（pctDef 55.5%） | 玩家實際穿著約 11（pctDef 5.5%）——**坦裝根本不存在於裝備庫** |

**結論**：秒殺不是單一參數的鍋，是「血池小 × 防禦斜率平 × 怪必中階級 × 爆擊×2 × INT 頂滿浮動 × 等級壓制」六層疊乘。任何原型單靠自己的工具都跨不過 14 倍的鴻溝——**必須先動共通地基，再讓原型工具補最後一段**。

| 驗收條件 | 結果 |
|---|---|
| A. 每職業有活法（陣亡 ≤20%） | 🟢 **全數通過**（G1~G6 生效，生存已不是問題） |
| B. 生存 build 輸出 ≥40% 基準 | 🔴 11 職業不過 |

**核心結論：問題已從「活不下來」轉成「只有一條活路」。**
17/17 職業的最佳生存 build 都是「重甲坦」或「混合」＝全部靠堆血量，
與本文「每位玩家挑一個自己喜歡的生存原型」的目標正好相反。

**陣亡率幾乎完全由血量決定**（唯一例外是影舞者，靠閃避）：

| 血量 | 陣亡率 |
|---|---|
| 1,075 | 1% |
| 1,025 | 15% |
| 875 | 29% |
| 850 | 39~51% |
| 825 | 53~56% |
| 800 | 10%（影舞者，閃避型） |

純攻擊二轉（劍鬼 850／狂戰士 850／聖劍士攻 875）全部卡在死亡區間，且**沒有任何減傷工具**。
輸出差距 **26.2 倍**（影舞者 49,392 vs 軍師 1,887），目標是 1.5~2.0 倍。

> ⚠️ **2026-08-07 量測更正**：軍師 1,887 是**拿錯武器量出來的假象**——舊對照表配單手劍（吃 STR），
> 但軍師配點在 INT、遊戲本來就沒有職業武器限制，理性玩家會拿法杖（吃 INT、mult 3）。
> 法杖版實測：軍師 12,516／兵聖 15,691（陣亡 62~65%），與頂點差距實為 **3~4 倍**不是 26 倍。
> 量測名單已改法杖（survivalPresets）。軍師系仍偏弱但屬於「調數字」範圍，不是結構重做。

**聖劍士的姿態是支配關係**：防禦姿態強制帶盾（多 200 血）＋格擋 70%（攻擊姿態僅 30%），
再用盾擊 60% 把輸出補回來 → 攻擊姿態多 40% 輸出卻換 29 倍陣亡風險，理性玩家不會選。

## 二之三、量測方法論的坑（踩過的，別再踩）

1. **模擬器漏帶「自己的隊伍光環」** — 正式環境是 `allParticipantsWithSelf`，自己一定在參戰者名單裡
   （`monsterZoneHandlers.js:3012`），所以單人打王本來就吃得到自己的光環。
   `simWorldBoss.js` 原本沒傳 `partyEffects` → 治療／軍師／結界／詩人／聖靈師被系統性低估。
   **2026-08-05 已修**（同一個坑 `balance-job-matrix-eco.js` 更早修過一次）。修正後結界師×混合
   陣亡 72%→26%。
2. **n=200 對陣亡率不夠** — 矮人戰士「輸出基準」build 在 n=200 測到 19%、n=2000 測到 26%，
   足以翻轉 A 條件與整份排行。**驗收一律用 n=2000**。
3. **20% 陣亡門檻是斷崖** — 「最佳生存 build」的選法是「通過門檻者取最高輸出」，
   卡在門檻邊緣的職業會在高低輸出之間跳（矮人戰士 18,521 ↔ 4,015，差 78%）。
   看排行時務必同時看該職業的全原型列，不要只看摘要那一列。
4. **B 條件對某些職業沒有鑑別力** — 相對輸出的分母是該職業「輸出基準」build 的傷害，
   軍師那個 build 均傷只有 409 → 比值虛高到 484%，B 綠燈毫無意義。

# 附錄二：貢獻分公式 v1 ⚠️ 已被【附錄C v3】取代，勿照此實作

> ⛔ **2026-07-26 作廢**：本版用「受益人次」當支援單位，實際討論後發現三個致命問題——

```
C = D + S + K

D 傷害分 = (直接傷害 + DoT傷害(中毒/燃燒/流血) + 傷害型光環歸戶(掩護射擊)) ÷ A_zone

         + 回復領域有效場次 × 0.3   （有效回復 > 0 才計）
         + 非傷害debuff受益場次 × 0.25 （破甲/減攻/減命中/緩速；同種取最高者計分）

K 控制分 = 全區停手窗口受益場次 × 0.5 （巨神震擊/冰封期間他人出戰數）
         + 部位破壞 × 2.0            （⚠️ 開放參數：可能與 D 雙重計分，待拍板）
         + 弱點翻面/機制觸發 × 1.0
```

## 一、為什麼用 KDA 格式（設計意圖）

這是**社群遊戲**：操作簡單是規格，一起打同一隻怪是地基，玩家一邊看直播一邊玩。
KDA 的價值不在精確，在於**零學習成本 + 可口語化**——「我今天 124/3/87」是一句能直接打進聊天室的話，
共同語彙就是社群黏著度。同時三個數字天然開出多個舞台，讓更多人的名字有機會出現在螢幕上
（社群遊戲裡「被看見」本身就是獎勵）。

## 二、三欄定義

| 欄 | 意義 | 單位 | 資料現況 |
|---|---|---|---|
| **K** 輸出 | 對王造成的傷害 | **萬**（124 萬 → K=124） | ✅ 現成（`damageMap`） |
| **D** 陣亡 | 世界王戰鬥中被擊敗次數 | 次 | ✅ 現成（DC `monsterZoneHandlers:1048`＋網頁 `playerAppRoutes:3689` 都已記 `death_count`） |
| **A** 助攻 | **你幫團隊增加的傷害＋減少的承傷** | **萬**（同 K） | ⚠️ 要在 combatLoop 埋歸戶點 |

單位用「萬」而非場當量：零解釋成本，且榜單每季重置 → 跨季通膨不需處理。

## 三、A 的核心：傷害當量統一（v3 最重要的改動）

不要問「你幫了幾個人」，改問：**因為有你，團隊多打出多少傷害＋少受了多少傷害？**
兩者都是傷害，與 K 同單位、直接可加，**不需要任何憑空拍的權重係數**。

| 輔助行為 | 換算方式 |
|---|---|
| 增傷/爆擊光環 | 受益者該場總傷害 × `加成/(100+加成)` |
| 破甲類 debuff | 受益者因防禦被破而多打出的傷害 |
| 治療 | 見第四節（保底＋救命加成） |
| 護盾 | 實際吸收掉的傷害（同治療公式） |
| 減傷光環 | 實際減免掉的傷害 |
| 全區停手（巨神震擊/冰封） | 敵人**少打的回合數 × 敵人該場實際每回合平均傷害**（取實際值＝保守估） |
| 部位破壞 | **不另計**（傷害已算在 K，避免雙重計分。此點解掉 v1 的開放參數①） |

**這個設計最大的好處**：輔助職強弱從「計分問題」變成「平衡問題」。
若實測輔助貢獻太低，正解是**把光環數值調強**（遊戲平衡旋鈕），而不是去調計分係數（作弊）。
調完貢獻分自動跟上。

**先例**：`combatLoop.js` 的掩護射擊已經是「傷害歸戶給提供者」的模式，基礎建設已存在，v3 只是推廣。

## 四、治療怎麼算（最難的一項）

同樣補 100 血價值可差 100 倍：補滿血的人＝0；補反正會活的人≈0；補在對方剩一刀就死時＝救下他剩餘全部輸出。

```
治療當量 = 有效治療量 × 1.0                  ← 保底，永不歸零
         + 多活回合數 × 受益者每回合傷害        ← 救命加成
```

- **多活回合數怎麼算**：戰鬥中多存一個「假設沒被治療的影子血量」累加器，
  結算時比對（影子血在第 8 回合歸零、實際活到 15 → 治療買了 7 回合）。
  **不需重跑模擬，只是一個計數器。**
- **為什麼一定要保底那段**：下季生存改版做完後大家本來就活得滿 15 回合，
  純用「多活回合」算會讓治療師**全部歸零**。保底是他的地板。
- **為什麼保底用 1:1（保守）**：嚴格推導 1 點血 ≈ `每回合傷害 ÷ 每回合承傷` ≈ 14 倍傷害當量，
  但先用 1:1 起步。**社群信任原則：寧可讓治療師覺得少，也不要讓輸出玩家覺得「他站著補血就贏我」。
  調高容易，調低會被罵。** 上線後看榜單再往上調。

## 五、D 的處理：死亡「率」係數（使用者定案：確實要扣分）

使用者定案：D 要實質扣分。理由——下季生存修好後死亡率不會太高，
**但玩家沒準備就會一直死 → 死亡率上升**，這正好量測「準備程度」。

用**率**不用次數：次數會懲罰打得多的人，率才是準備程度。

```
死亡率     = D ÷ 世界王參戰場次
超額死亡率  = max(0, 死亡率 − 免責門檻)        ← 門檻內視為運氣波動，不罰
存活係數    = max(0.5, 1 − 超額死亡率 × 0.8)
貢獻分 C    = (K + A) × 存活係數
```

| 玩家狀態 | 死亡率 | 存活係數 |
|---|---|---|
| 準備充分 | 8% | ×1.00（免責內） |
| 小失誤 | 20% | ×0.92 |
| 裝備沒跟上 | 40% | ×0.76 |
| 完全沒準備 | 70%+ | ×0.50（底線） |

**兩個刻意的設計**：
1. **懲罰要克制**——D 已被隱性懲罰過一次（死得早＝K 本來就低），顯性再重罰等於同一件事罰兩次。
2. **底線 ×0.5 不讓任何人歸零**——社群遊戲裡「打了半天 0 分」是最傷的體驗。

## 六、四個舞台（多開幾個榜＝多幾個人被看見）

| 榜 | 判準 |
|---|---|
| 🗡 輸出王 | K 最高 |
| 🤝 助攻王 | A 最高 |
| 🛡 不倒王 | **死亡率最低**（需滿最低參戰場次，否則不打＝0%） |

- 個人頁顯示：`124 / 3 / 87` ＋ 存活率 ＋ KDA 值
- **KDA 值 = (K+A) ÷ max(1,D)** 保留當「聊天室爽度數字」；**排名與寶箱用 C**
- 顯示位置：戰報結尾（本場）／世界王結算公告（四王各報一位）／**直播 overlay 即時榜**（社群燃料）／個人資料頁（賽季累計）

### 同 key 光環的計分分帳（B 案・使用者定案 2026-08-07・✅ 已實裝 combatLoop KDA 結算段）

玩法維持「同 key 只取數值最高」（防乘法爆炸），但**計分按各提供者數值比例分帳**：
pot ＝ 最高外部光環的實際效果量，依 v 比例分給該 key 的所有外部提供者——

救命加成記給分帳後占比最大的治療提供者。實測：20/10 兩位提供者分帳 2:1、總和＝pot。

## 七、防刷（沿用既有原則）

1. **不可自益**——自己的場次、自我治療永不計入自己的 A ✅ 已實裝

3. **有效量原則**——溢出治療、對滿血的減傷不計 ✅ 已實裝
4. **同一受益者每小時計分上限**（防雙開互刷）❌ 未實裝
5. **光環 3 分鐘在場規則**（已上線）是 A 的前置 ✅

## 八、寶箱分配（最小改動）

## 十、待校準參數（生存改版後用真實數據定，勿先拍死）

1. **免責門檻 10%**——要看 `survival-matrix` 實測「準備充分」玩家的真實死亡率分布。
   若實際是 25%，門檻就該設 25%，否則會全員被罰。
