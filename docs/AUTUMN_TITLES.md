# 秋季稱號與任務

現行規格：2026/10/4。執行事實為 `src/shared/autumnTitleRules.js`、`src/services/weeklyQuest/autumnTitleService.js` 與 MongoDB 的道具／任務資料。

## 取得與效果

冒險手冊 → 任務 → 賽季。完成後手動領取，再於背包 → 裝備 → 稱號穿戴。每個人物本季可領一次；七件稱號均不可拍賣且換季保留。

## 計數與防重

- 限本季 `s20261001`、2026/10/4 21:00 台灣時間起且全服實際開放時發生的行為。**時間到不會自動打開登入口**；維護白名單的開季前測試不計。
- 進度於 `progress.autumnTitleProgress.slots.<人物槽位>`；切換人物不混計。已保存的副本通關證據以事件當時是否開放判定，結算重試沿用收據。
- 同台灣日期報到只計一次；同件裝備降級後再到 +5 不重計，交易取得現成 +5 不計。
- 普通怪、BOSS 等怪物勝利沿用共同勝利入口，不計 PK。組隊全滅前已通過的樓層仍計數；挑戰稱號需最後一樓完整勝利，中途退出不計。
- 領取先驗證完整道具表與條件；金幣使用人物／稱號固定收據，稱號道具與領取記號同次 CAS 儲存。連點、並行請求與金幣入帳後中断重試不重發。
- 新增道具與五個任務，另外更新既有百戰／爬塔兩任務；不重建每日每週任務、不改原獎勵、不重設玩家資料。

## 驗證與部署

### 每日全清卡包

本季三項每日任務（出戰30次、勝利20場、報到1次）全部達標後，可在每日任務頁領取「每日全清獎勵」：記憶錨定卡包1包。無須先逐項領取其餘獎勵；每日依台灣日期重設，全清獎勵本身不納入完成條件。既有每日金幣合計3,000維持，不額外增加EXP。

任務ID為`autumn-202610-daily-daily_complete_count`，沿用現有秋季任務收據及背包CAS結算，防止連點、並行與發獎後寫入領取記號失敗造成重複卡包。`scripts/test-side-systems.js`驗證未全清拒絕、十次並行、中斷重試與隔日重領；正式資料僅新增此任務，未重設既有進度或變更登入設定。

秋季一般任務的道具獎勵在複製背包前排除MongoDB管理的`_id`，避免ObjectId經`structuredClone`變為普通物件而被存檔拒絕。回歸測試使用正式MongoDB Repository驗證全清卡包實際入背包及原ObjectId保持不變；失敗時不標記已領，玩家可重試。

`node scripts/test-autumn-titles.js` 使用獨立暫存 MongoDB，驗證七稱號領取、人物隔離、十次並行請求、入帳後中斷恢復、報到與強化實際入口、實際副本結算、普通擊殺及兩種掛機收益、換季保留。另執行既有任務批次、一般區共鬥、組隊養成、經濟及其他系統回歸。

稱號服務複製進度時保留遊戲欄位，排除 MongoDB 管理的 `_id`，避免 `structuredClone` 改變 BSON ObjectId 而使存檔失敗。回歸測試另使用正式 `createMongoRepositories` 的進度儲存實作，在獨立 MongoDB 驗證勝利進度寫入、收據防重、五次並行領取僅成功一次，並確認 `_id` 維持原值。

資料部署由 `scripts/migrate-autumn-titles.js` 預覽，再以已解析驗證的 BSON 備份執行 `--apply --backup=...`，核對七件道具、七任務及維護鎖不變。來源碼部署後重啟單一正式 runtime，讀回 API、公開圖檔及門禁。

七件道具統一為 `itemType: equipment`、`equipSlot: title_eq`，不可使用或強化；舊已領實例僅修正分類，不重設任務或重發金幣。全部七項合計44,000金幣、D石2／C石2／B石8／A石5。前端也支援舊title分類以避免快取把稱號當消耗品。隔離測試涵蓋領取後實際裝備／卸下、七項獎勵總量、並行防重與中斷重試。

## 本季爬塔首次通關自選箱

任務→賽季另有帳號共用的「本季首登・一般30樓」與「本季首登・挑戰50樓」，完整通關後分別手動領A級／S級武器自選箱×1。帳號本季各限一次，換人物與再次通關不重領；原七個人物獨立稱號任務及其獎勵保持原規則。兩項新任務使用一般賽季任務紀錄、固定獎勵收據與背包CAS，換季隨賽季任務歸零。自選箱操作見[組隊爬塔](PARTY_TOWER.md)。
