## 架構設計

### 職業檢測邏輯

```javascript
// combatStats.js lines 103-128
const jobId = String(jobEq?.itemId || jobEq?.id || "").toLowerCase();

const hasSwordsmanBadge = jobId.includes("swordsman") || jobName.includes("劍士");
const hasWarriorBadge = jobId.includes("warrior") && !jobId.includes("dwarf");
// ... etc
```

### 傷害倍率應用順序
1. **基礎傷害**: ATK × (1 - DEF/100) + variance
2. **職業傷害倍率**: 弓 ×1.2, 法杖 ×1.15, 戰士低血 ×1.15
3. **爆擊判定**: LUK 驅動 ×2.5 (弓箭手另有命中要害)
4. **額外倍率**: 連擊 ×1.1, 命中要害 ×1.5

### 條件判定系統
- **高血量判定**: HP ≥ threshold% (矮人 90%)
- **低血量判定**: HP ≤ threshold% (戰士 35%)
- **武器檢測**: 武器類型精確匹配 (dagger, sword_1h, mace_2h, etc)
- **組合檢測**: 單手劍+盾 (劍士格擋反擊)

## 設計理念

1. **多樣化遊玩風格**:
   - 劍士：防守反擊型
   - 戰士：血量逆轉型
   - 矮人：穩定保護型
   - 盜賊：連續攻擊型
   - 法師：穿防遠距型
   - 治療師：團隊支援型
   - 弓箭手：精準暴擊型

2. **條件觸發機制**:
   - 血量條件 (高血/低血)
   - 武器組合條件
   - 職業徽章條件

3. **獨立但互補的系統**:
   - 各職業機制獨立開發
   - 可與其他職業效果疊加
   - 通過 effectEngine 保持一致性
