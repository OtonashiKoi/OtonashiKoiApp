# 極簡工作流 - 多角色協作

**原則**: 最少的配置 + 最簡的關鍵字 + 自動記憶

---

## 🎯 使用方式

### 格式
```
[Agent] @領域 簡短描述
```

### 例子

```bash
# 後台 UI/UX 設計師
[設計] @admin 後台玩家管理介面

# 道具系統開發
[找] @item 現有道具資料結構
[設計] @item 新的稀有度系統
[實現] @item 道具掉落邏輯

# 玩家系統
[設計] @player 玩家資訊頁面架構
[實現] @player 玩家等級升級邏輯

# 遊戲核心
[找] @game 職業系統實裝
[設計] @game 新職業平衡方案
[實現] @game 新職業技能
```

---

## 🏷️ 領域標籤（簡潔版）

| 標籤 | 用途 | 擁有者 |
|------|------|--------|
| `@admin` | 後台管理 UI/UX、儀表板 | 後台設計師 |
| `@item` | 道具、裝備、物品系統 | 全棧/後台工程師 |
| `@player` | 玩家資訊、檔案、社群 | 後台設計師/APP 開發 |
| `@game` | 職業、戰鬥、經濟、核心系統 | 全棧工程師 |

## 💾 記憶系統（自動加載）

不需要每次都重新描述背景：

```json
"autoLoad": [
  "QUICK_REFERENCE.md",        // 快速查詢
  "ADMIN_SPECS.md",            // 後台規格（自動建立）
  "ITEM_SYSTEM.md",            // 道具系統
  "PLAYER_SYSTEM.md"           // 玩家系統
]
```

一旦寫入記憶，**後續只需提關鍵字就行**

---

## 🔄 協作流程（最簡版）

### 例：設計後台玩家管理介面

**步驟 1** - 設計師設計
```
[設計] @admin 後台玩家管理介面
  ↓ 輸出 Figma 設計、API 需求
```

**步驟 2** - 開發者看設計
```
[找] @player 看設計師的需求文檔
[實現] @player 玩家管理 API + 前端元件
```

**結束** - 自動記憶保存，下次查詢只需：
```
[找] @player 玩家管理系統
  → 自動返回現有實裝位置
```
